# KatalkViral 자동화 계획 (v1)

## 1. 구조 요약: "로컬 제작 + 사람 검수 + Actions 업로드"
YouTube 시크릿은 Actions에만 있고, 공개 업로드는 저작권/평판 리스크가 있으므로 **기본은 비공개(unlisted) 업로드 -> 이든이 확인 -> 공개 전환**.
로컬(Claude)이 글 선정/각색/렌더, Actions는 업로드만. 풀 파이프라인(katalk_shorts_automation.yml)은 지금처럼 수동 전용으로 두고 스케줄은 켜지 않음(Pann 크롤링+TTS가 Actions IP에서 안정적이라는 증거 전까지).

## 2. 단계와 데이터 계약
| # | 단계 | 실행 위치 | 입력 -> 출력 |
|---|------|-----------|--------------|
| 1 | Fetch | 로컬 | 네이트판 랭킹 -> `Candidate[] {id,url,title,body,commentsTop}` |
| 2 | Filter(안전+재미) | 로컬 | Candidate -> 통과/탈락 + 사유 (규칙 3절, LLM 판정 2차) |
| 3 | Adapt(각색) | 로컬 | 통과 글 -> `ScriptJson` (대화형, 3인 이상) |
| 4 | Validate | 로컬 | ScriptJson -> 구조검사 (4절) |
| 5 | Render | 로컬 | ScriptJson -> `video.mp4` (9:16, 15~45초) |
| 6 | Queue | 로컬 | `upload_queue/<slug>/{video.mp4,script.json,meta.json}` + git push |
| 7 | Review | 사람 | 영상 확인 후 `meta.json.approved=true` 또는 Actions 입력 `privacy` 선택 |
| 8 | Publish | Actions | 큐 항목 1개 업로드(기본 unlisted, approved면 public) + 고정댓글(출처) |
| 9 | Record | Actions | `used_sources.json`에 id 기록, 큐 항목을 `upload_queue/done/`으로 이동 |

`script.json` 필수 필드: planId, title, hookHeadline, messages[{sender,name,text}], source{site,url,author?,id}, description, pinnedComment.
`meta.json`: {sourceId, createdAt, safety:{pass,reasons}, funnyScore, approved:false, videoId?}

## 3. 소재 선정 기준
**안전 필터 (하나라도 걸리면 탈락, 키워드 1차 + LLM 2차):**
- 정치/선거/정당/대통령/지역감정/종교/혐오, 성별·세대·직업 갈등("한남/김치/틀딱/맘충" 류), 노조/젠더/군대 논쟁
- 실명/회사명/학교명/개인 특정 가능 정보, 미성년자 관련, 성적·폭력·자살·질병·사망, 불륜/막장 사연, 법적 분쟁, 소송
- 특정인 비난·하소연·분노 글(콜센터 진상 푸념 같은 "갑질 하소연")
- 댓글 반응이 논쟁/싸움 위주인 글
- 위반 시 의심되면 탈락(보수적). 탈락 사유는 meta/log에 남김.

**재미 기준 (각 0~2점, 합 >=6/10 통과):**
1. 반전/펀치라인이 있음(마지막에 웃음 포인트) 2. 일상 속 황당·귀여운 상황 3. 대화로 옮길 수 있는 상대역이 존재(엄마, 친구, 직장동료 등 2명 이상 등장 가능) 4. 길이 적당(원문 200~1500자, 사건 1개) 5. 베스트 댓글이 "ㅋㅋㅋ" 위주(웃음 반응).
- **독백/하소연/정보성/긴 서사는 재미 점수에서 자동 감점**. 카테고리: 유머/엽기/웃긴썰/가족·친구 일화 위주.
- 후보 20개를 받아 상위 1개만 채택, 통과 0개면 그날은 생성 안 함(억지로 만들지 않기).

## 3-1. 소재 소스 우선순위 (analyst 조사 반영, docs/ANALYSIS.md)
- 네이트판 robots.txt는 `* Disallow: /`, 다른 커뮤니티도 대부분 AI 크롤러 차단. 재미+안전 글은 하루 0~1개라 단일 소스로 매일 공급 불가.
- **1순위: 소스 없는 창작** (Gemini가 새 카톡 코미디 설정 생성: 황당한 상황 1개 + 친구들 놀림). 크레딧 불필요, 저작권/크롤링 리스크 없음.
- **2순위: 커뮤니티 글은 영감용으로만** (아이디어만 차용, 문장/고유 디테일 복사 금지). 이든 승인 전까지 기본 OFF(env 플래그).
- 3순위: BACKUP 풀(3개, 반복됨) 최후 수단.
- 품질 게이트: 프리필터 -> 대본 생성 -> validator 지표 -> LLM 심사(웃김/반전/펀치라인/논쟁성/실명) -> 재시도 1회 -> 다음 후보. 영상당 Gemini 호출 수 최소화(쿼터).

## 3-2. 소재 옵션 (이든 선택용) + 권장
Gemini 호출 기준: 무료 쿼터 20회/일(`generateContentWithFallback`이 모델 폴백하면 모델별 쿼터 소모). 영상 1편 = 대본 1 + 심사 1 = 최소 2회, 재시도 1회 포함 시 최대 4회. 즉 하루 20회면 **일 4~5편이 이론상 한도**, 계획(주 3회, 1~2편 배치)은 여유 있음.
| 옵션 | 내용 | 호출/편 | 리스크 | 품질 |
|---|---|---|---|---|
| A 소스 없는 창작 (권장, 기본) | Gemini가 설정 생성 + validator + LLM 심사 | 2~4 (설정과 대본을 한 호출로 합치면 2) | 저작권/크롤링 없음 | 아이디어 반복 위험 -> 프리미스 해시 중복체크, 주제 목록 시드 |
| B 이든 제출/본인 글 | `inbox/*.txt`(이든이 직접 쓴 일화, 지인 동의 받은 썰)를 각색 | 2~4 | 가장 낮음 (원작자=본인) | 진짜 일화라 가장 웃김, 단 이든이 공급해야 함 |
| C 허용 소스 | 오늘의유머(robots 없음), 에펨코리아(/best,/humor만 허용) | 3~5 (선정 판단 1 추가) | ToS/저작권 별도 확인 필요, 글쓴이 동의 없음, 안전 글 비율 낮음 | 불확실, 크롤러 차단 변동 |
**권장: A를 기본 경로, B를 보너스 입력(inbox에 파일이 있으면 우선 사용). C는 보류**(이든이 원하면 ToS 확인 후 영감용만). Pann 라이브 fetch는 중지(기본 OFF).
- 공통: 검수 게이트와 unlisted 기본 유지. 후보는 호출 절약을 위해 프리필터(키워드)를 먼저 통과해야 함.

- 실측(analyst, ANALYSIS.md Appendix A): 랭킹 20개 중 엄격 통과 0, 보더라인 1 / 유머 게시판은 이미지·링크 위주 + 뽐뿌 재게시 -> 텍스트 통과율 0~5%. 따라서 C 옵션은 사실상 불가, 블랙리스트 정규식(Appendix A3)은 B(inbox) 입력과 영감 모드의 프리필터로 재사용. 댓글 웃음 기준은 가산점 전용.

## 4. 각색(독백->대화) 수락 기준
- 참여자 3명 이상, "나" 발화 <=50%, 메시지 12~26개·30자 이하, 상대역 각자 2줄 이상, 같은 사람 연속 2메시지 이하, 리액션(ㅋㅋ류) <=25% (scriptAgent validator 기준, 실패 사유는 재시도 프롬프트에 전달)
- 메시지 12~25개, 메시지당 <=30자, 첫 2메시지 안에 훅, 마지막 메시지는 펀치라인(반전)
- 원문 사실 유지(줄거리 왜곡·없는 사건 추가 금지), 실명·상호 제거(가명 처리), 욕설 제거
- 원문을 문장 그대로 복사 금지(재작성). description/고정댓글에 출처(사이트명+URL) 필수, "원문 각색" 명시
- 검증 실패 시 재시도 최대 2회 -> 그래도 실패면 해당 글 폐기하고 다음 후보로

## 5. 중복/실패 처리
- 중복: `used_sources.json`에 Pann 글 id+URL. 선정 시점(4단계 이전)에 이미 쓴 id 제외, **업로드 성공 후** 기록(렌더만 한 건 'queued' 상태로 구분해 재선정 방지).
- Fetch 실패: 3회 재시도 후 종료(비0 exit), 대체로 폴백 소재(AI 생성)는 쓰지 않음.
- LLM/TTS 실패: 단계별 재시도 2회, 실패 시 큐에 안 넣고 로그만.
- Publish 실패: 큐 항목 유지(삭제 금지), 같은 항목 재실행 가능(멱등: meta.videoId 있으면 스킵). 쿼터 초과는 다음날 재시도.
- 한 번에 큐 1~3개 상한, 일 업로드 최대 2개.

## 6. 검수 게이트와 업로드
- publish_only.yml을 개선: 입력 `item`(폴더명, 기본 가장 오래된 미업로드), `privacy`(기본 unlisted)
- 이든은 YouTube Studio에서 unlisted를 확인 후 공개 전환(또는 `privacy=public` 재실행이 아니라 Studio 전환 권장: 재업로드 방지)
- 향후 승인 이력이 쌓이면 `auto_public: true` 옵션을 켤 수 있으나 v1에서는 기본 꺼짐.

## 7. 주기
- 로컬 제작: 주 3회(월/수/금), 한 번에 1~2편 배치 -> 큐에 쌓음
- Actions 업로드: 수동 실행 우선. 안정화 후 `schedule` 하루 1회(KST 19:00 = cron `0 10 * * *`), 큐가 비면 아무것도 안 하고 성공 종료
- 처음 2주는 수동만. 조회수/반응은 feedbackAgent가 읽되 feedback_memory.json은 Actions가 아니라 로컬에서만 갱신

## 8. 작업 분담/수락 기준
**team-dev (src/):**
1. pannFetcher: 후보 20개와 댓글 상위 3개 반환, 재시도
2. `storyFilter.ts`: 3절 안전 규칙(키워드+LLM) 및 재미 점수, 통과 항목만 반환. 수락: temp_katalk_test/pann_out.json의 콜센터 글은 탈락해야 함
3. scriptAgent 프롬프트: 독백을 상대역 있는 대화로 재구성, 4절 `validateScript()`(코드로 검사) 추가. 수락: 샘플 5개 중 5개가 검증 통과
4. 큐 구조 `upload_queue/<slug>/`, publish_only.ts가 item/privacy 지원, 업로드 후 used_sources 기록. 로컬 .env 없이 dry-run 플래그로 확인 가능
5. 업로드는 절대 로컬에서 실행하지 않음

**team-analyst:** 네이트판 카테고리/랭킹에서 재미있는 글 20개 샘플을 3절 기준으로 채점, 탈락 사유 통계, 키워드 블랙리스트 보강안, 통과율이 20% 미만이면 소스 확장(다른 유머 사이트) 제안. 약관/저작권 관점(출처 표기, 크롤링 robots) 메모.

## 9. 이든에게 열린 결정
1. 공개 전환 방식: 항상 unlisted 후 수동(권장) vs 일정 기간 후 자동 공개
2. 풀 파이프라인(Actions 자동 제작)을 포기하고 로컬 제작 유지할지(PC가 꺼지면 중단됨)
3. 소재 방식: 소스 없는 창작을 기본, 네이트판은 영감용/OFF로 할지 (robots.txt가 크롤링 금지)
4. 업로드 빈도(주 3회 vs 매일)
5. 원작자 사전 동의 없이 각색 업로드의 리스크 수용 여부(출처 표기만으로는 법적 면책 아님)
